几天前，我在 [推荐一个 Mac 神器：重复操作一键自动化](https://mp.weixin.qq.com/s/L65ZFiQJGPUljxmAiXWZzg) 一文中，分享了利用 Alfred 实现「一键唤起 Freeform 并创建画板」的工作流。

作为一名 **Vibe Coding** 的实践者，我习惯将繁琐的流程自动化。然而，这几天在享受自动化带来的“快感”时，我遇到了一个典型且恼人的阻断——**间歇性失效**。

起初，我以为是 Alfred 的执行力问题，或者是 Mac 内置应用 Freeform 的响应滞后。但在经历了数轮的调试后，真相终于浮出水面：这不仅仅是一个软件 Bug，更是**物理世界与数字指令的一次碰撞**——我们触发工作流的快捷键（`cmd+shift+alt+N`）与后续脚本执行的快捷键（`cmd+N`）发生了“拥堵”。

这并非 Alfred 的锅，而是自动化设计中的经典难题：**修饰键穿透（Modifier Key Penetration）**。

![](http://cdn.cs-magic.cn/picgo/20251201055623385.png)

简单来说，当脚本试图发送 `cmd+N` 时，我的手指还没来得及从 `cmd+shift+alt` 上挪开，系统最终接收到的是一个混乱的组合键。

![](http://cdn.cs-magic.cn/picgo/20251201060023118.png)

为了解决这个问题，我召集了我的“AI 董事会”——**Claude (CC)、ChatGPT 和 Gemini**，进行了一场紧急的技术研讨会。经过数轮 Prompt 的博弈与验证，我整理出了以下四种方案。这不仅是修复 Bug 的过程，更是一次对各大模型在 MacOS 自动化领域能力的**压力测试**。

### 方案一：Gemini 的降维打击——GUI Scripting

既然物理按键会冲突，那就绕过键盘，直接操作 UI。

在这个方案中，**Gemini** 展现了令人惊喜的细腻度。它不仅给出了通过 Accessibility API 点击菜单栏的代码，还敏锐地意识到了**系统语言环境（Locale）**的差异，直接给出了中英文双语适配方案。

![](http://cdn.cs-magic.cn/picgo/20251201060344448.png)

```applescript
tell process "Freeform"
	try
		-- 方法：直接点击菜单栏，这会忽略你手上按着的 Alt/Shift 键
		-- 请根据你的系统语言选择下面的一行：

		-- 如果是中文系统：
		click menu item "新建看板" of menu "文件" of menu bar 1

		-- 如果是英文系统 (把上面中文的注释掉，启用下面这行)：
		-- click menu item "New Board" of menu "File" of menu bar 1

	on error
		-- 如果找不到菜单，可能是应用没完全加载或语言不对，此时可以尝试回退到模拟按键（虽然可能会失败）
		keystroke "n" using {command down}
	end try
end tell
```

这种对上下文（Context）的极致理解，正是 Vibe Coding 过程中我们最看重的 AI 特质——**不仅代码能跑，还要能适应复杂的真实环境**。

### 方案二：妥协的艺术——键位策略调整

![](http://cdn.cs-magic.cn/picgo/20251201220555938.png)

```applescript
tell application "Freeform"
    activate
    delay 0.1
    tell application "System Events"
        keystroke "n" using {command down}
    end tell
end tell
```

也有 AI 提出了“换个快捷键”的思路。比如用 `cmd+K` 触发，松手后保留 `cmd`，正好衔接 `cmd+N`。

虽然逻辑闭环，但我投了反对票。**Vibe Coding 的核心是顺应人的直觉，而不是让人去适应机器。** 为了一个脚本去修改已经形成的肌肉记忆，这是本末倒置。

此外，如果触发键直接设为 `cmd+N`，恭喜你，你将创造一个完美的无限递归死循环。

### 方案三：Alfred 原生主义——Dispatch Key Combo

![](http://cdn.cs-magic.cn/picgo/20251201220656036.png)

这套方案是我认为最优雅的**低代码（Low-Code）**解法。它不需要写一行 AppleScript，而是利用 Alfred 内置的原子能力构建工作流：

1.  **Hotkey**：捕获 `cmd + shift + alt + N`。
2.  **Launch App**：唤醒 Freeform。
3.  **Delay**：插入 0.2s 缓冲，**用时间换空间**，等待物理按键释放。
4.  **Dispatch Key Combo**：由 Alfred 内部接管，发送纯净的 `cmd + N`。

在寻找这个功能入口时，**ChatGPT 出现了典型的幻觉**，它自信地指向了一个不存在的路径。反而是 **Gemini** 再次精准命中，指出了正确的位置。

![](http://cdn.cs-magic.cn/picgo/20251201221253417.png)

这里必须纠正 ChatGPT 的错误：Alfred 的 `Dispatch Key Combo` 功能位于 **Outputs** 节点下，而非 Actions。

![](http://cdn.cs-magic.cn/picgo/20251201221312261.png)

### 方案四：极客的选择——Hammerspoon

虽然 Claude (CC) 在本次 factual checking 中稍显逊色，未能在第一时间给出 Key Combo 的标准答案，但它提出了一个极具**可编程性（Programmability）**的替代方案——**Hammerspoon**。

![](http://cdn.cs-magic.cn/picgo/20251201221824950.png)

Hammerspoon 允许我们使用 Lua 语言对 MacOS 进行细粒度的控制。它就像是给 MacOS 装上了一个可编程的神经系统。

![](http://cdn.cs-magic.cn/picgo/20251201221928871.png)

在 Claude 的辅助下，我将配置进行了模块化处理，把快捷键逻辑剥离到 `hotkeys.lua` 中。这种**工程化思维**是 Claude 一贯的强项。

![](http://cdn.cs-magic.cn/picgo/20251201222141832.png)

Hammerspoon 的 Console 提供了类似 IDE 的调试体验，对于喜欢掌控一切的硬核 Vibe Coder 来说，这绝对是心头好。

![](http://cdn.cs-magic.cn/picgo/20251201221901761.png)

虽然最终我选择了 Alfred 的原生方案（方案三）以追求极致的简洁，但 Hammerspoon 在处理更复杂的窗口管理和事件监听时，依然是不可替代的神器。

此外，读者们推荐的 **Raycast** 也是近期的大热门，其插件生态和 UI 交互确实有着后来居上的气势，值得我们在未来的 Vibe Coding 专栏中深入探讨。

### 💡 深度复盘

本次排错经历，与其说是解决了一个快捷键冲突，不如说是对当前主流 AI 模型的一次**实战阅兵**。

*   **Claude (CC)**：工程化思维强，擅长给出硬核的代码解决方案（Hammerspoon），但在特定软件（Alfred）的知识库检索上略显滞后。
*   **ChatGPT**：虽然思维发散，但在此次 MacOS 自动化的具体事实核查（Fact Checking）上出现了幻觉。
*   **Gemini (ai.studio)**：凭借强大的长上下文理解和精准的检索能力，在本次“人机结对”中表现最为出色，不仅给出了代码，还考虑了多语言环境。

这也再次印证了我的观点：**在 Vibe Coding 的时代，没有万能的模型，只有最适合当前任务的“员工”。** 而我们作为架构师，核心能力在于如何调度这些智慧。
