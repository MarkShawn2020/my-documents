AI-dependent computer programming technique

**Vibe coding** is an [artificial intelligence-assisted software development](/wiki/AI-assisted_software_development "AI-assisted software development") technique popularized by [Andrej Karpathy](/wiki/Andrej_Karpathy "Andrej Karpathy") in February 2025.[\[1\]](#cite_note-Edwards-2025-1)[\[2\]](#cite_note-The_Times_of_India-2025-2)[\[3\]](#cite_note-Karpathy-X-post-3) The term was listed on the [Merriam-Webster](/wiki/Merriam-Webster "Merriam-Webster") website the following month as a "slang & trending" term.[\[4\]](#cite_note-merriam-webster-4) It was named [Collins Dictionary](/wiki/Collins_English_Dictionary "Collins English Dictionary")'s [Word of the Year](/wiki/Word_of_the_year#Collins_English_Dictionary "Word of the year") for 2025.[\[5\]](#cite_note-5)[\[6\]](#cite_note-6)

Vibe coding describes a [chatbot](/wiki/Chatbot "Chatbot")\-based approach to creating [software](/wiki/Application_software "Application software") where the developer describes a project or task to a [large language model](/wiki/Large_language_model "Large language model") (LLM), which generates [code](/wiki/Source_code "Source code") based on the [prompt](/wiki/AI_prompt "AI prompt"). The developer does not review or edit the code, but solely uses tools and execution results to evaluate it and asks the LLM for improvements. Unlike traditional AI-assisted coding or [pair programming](/wiki/Pair_programming "Pair programming"), the human developer avoids examination of the code, accepts AI-suggested completions without human review, and focuses more on iterative experimentation than code correctness or structure.

Advocates of vibe coding say that it allows even [amateur programmers](/wiki/End-user_computing "End-user computing") to produce software without the extensive training and skills required for [software engineering](/wiki/Software_engineering "Software engineering").[\[7\]](#cite_note-7)[\[8\]](#cite_note-Chowdhury-2025-8) Critics point out a lack of accountability, maintainability, and the increased risk of introducing [security vulnerabilities](/wiki/Vulnerability_\(computer_security\) "Vulnerability (computer security)") in the resulting software.[\[8\]](#cite_note-Chowdhury-2025-8)[\[1\]](#cite_note-Edwards-2025-1)

## Definition

\[[edit](/w/index.php?title=Vibe_coding&action=edit&section=1 "Edit section: Definition")\]

Computer scientist [Andrej Karpathy](/wiki/Andrej_Karpathy "Andrej Karpathy"), a co-founder of [OpenAI](/wiki/OpenAI "OpenAI") and former AI leader at [Tesla](/wiki/Tesla,_Inc. "Tesla, Inc."), introduced the term *vibe coding* in February 2025. The concept refers to a coding approach that relies on LLMs, allowing programmers to generate working code by providing [natural language descriptions](/wiki/Natural_language_processing "Natural language processing") rather than manually writing it.[\[1\]](#cite_note-Edwards-2025-1)[\[2\]](#cite_note-The_Times_of_India-2025-2)[\[8\]](#cite_note-Chowdhury-2025-8)

Karpathy described it as "fully giv\[ing\] in to the vibes, embrac\[ing\] exponentials, and forget\[ting\] that the code even exists."[\[3\]](#cite_note-Karpathy-X-post-3) He used the method to build prototypes like MenuGen, letting LLMs generate all code, while he provided goals, examples, and feedback via natural language instructions.[\[9\]](#cite_note-karpathy-menugen-9) The programmer shifts from manual coding to guiding, testing, and giving feedback about the AI-generated [source code](/wiki/Source_code "Source code").[\[1\]](#cite_note-Edwards-2025-1)[\[2\]](#cite_note-The_Times_of_India-2025-2)[\[10\]](#cite_note-Roose-2025-10)

The concept of vibe coding elaborates on Karpathy's claim from 2023 that "the hottest new [programming language](/wiki/Programming_language "Programming language") is English", meaning that the capabilities of LLMs were such that humans would no longer need to learn specific programming languages to command computers.[\[11\]](#cite_note-Naughton-2025-11)

A key part of the definition of vibe coding is that the user accepts AI-generated code without fully understanding it.[\[1\]](#cite_note-Edwards-2025-1) Programmer [Simon Willison](/wiki/Simon_Willison "Simon Willison") said: "If an LLM wrote every line of your code, but you've reviewed, tested, and understood it all, that's not vibe coding in my book—that's using an LLM as a typing assistant."[\[1\]](#cite_note-Edwards-2025-1)

## Reception and use

\[[edit](/w/index.php?title=Vibe_coding&action=edit&section=2 "Edit section: Reception and use")\]

In February 2025, *[New York Times](/wiki/The_New_York_Times "The New York Times")* journalist [Kevin Roose](/wiki/Kevin_Roose "Kevin Roose"), who is not a professional coder, experimented with vibe coding to create several small-scale applications. He described these as "software for one", referring to personalised AI-generated tools designed to address specific individual needs, such as an app that analyzed his fridge contents to suggest items for a packed lunch. Roose noted that while vibe coding enables non-programmers to generate functional software, the results are often limited and prone to errors.[\[10\]](#cite_note-Roose-2025-10)[\[11\]](#cite_note-Naughton-2025-11)

In one case, the AI-generated code fabricated fake reviews for an [e-commerce](/wiki/E-commerce "E-commerce") site. He also observed that AI-assisted coding enables individuals to develop software that previously required an engineering team.[\[10\]](#cite_note-Roose-2025-10) In response to Roose, cognitive scientist [Gary Marcus](/wiki/Gary_Marcus "Gary Marcus") said that the algorithm that generated Roose's LunchBox Buddy app had presumably been trained on existing code for similar tasks. Marcus said that Roose's enthusiasm stemmed from reproduction, not originality.[\[11\]](#cite_note-Naughton-2025-11)

In March 2025, *[Y Combinator](/wiki/Y_Combinator "Y Combinator")* reported that 25% of [startup companies](/wiki/Startup_company "Startup company") in its Winter 2025 batch had codebases that were 95% AI-generated, reflecting a shift toward AI-assisted development within newer startups.[\[12\]](#cite_note-Mehta-2025-12) The question asked was about AI-generated code in general, and not specifically about vibed code.

Three engineers interviewed by *[IEEE Spectrum](/wiki/IEEE_Spectrum "IEEE Spectrum")* agreed that vibe coding is a way for programmers to learn languages and technologies they are not yet familiar with.[\[13\]](#cite_note-Smith-2025-13)

Inspired by "vibe coding", *[The Economist](/wiki/The_Economist "The Economist")* suggested the term "vibe valuation" to describe the very large valuations of AI startups by [venture capital](/wiki/Venture_capital "Venture capital") firms that ignore accepted metrics such as [Annual Recurring Revenue](/wiki/Annual_Recurring_Revenue "Annual Recurring Revenue").[\[14\]](#cite_note-14)

In July 2025, *[The Wall Street Journal](/wiki/The_Wall_Street_Journal "The Wall Street Journal")* reported that vibe coding was being adopted by professional software engineers and had begun to enter commercial use cases.[\[15\]](#cite_note-15)

In July 2025, SaaStr founder documented his negative experiences with vibe coding: [Replit](/wiki/Replit "Replit")'s AI agent deleted a database despite explicit instructions not to make any changes.[\[16\]](#cite_note-16)[\[17\]](#cite_note-17)

In September 2025, *[Fast Company](/wiki/Fast_Company "Fast Company")* reported that the 'vibe coding hangover' is upon us, with senior software engineers citing '[development hell](/wiki/Development_hell "Development hell")' when working with AI-generated vibe-code.[\[18\]](#cite_note-18)

## Limitations

\[[edit](/w/index.php?title=Vibe_coding&action=edit&section=3 "Edit section: Limitations")\]

### Mischaracterization of software development

\[[edit](/w/index.php?title=Vibe_coding&action=edit&section=4 "Edit section: Mischaracterization of software development")\]

[Andrew Ng](/wiki/Andrew_Ng "Andrew Ng") has taken issue with the term, saying that it misleads people into assuming that software engineers just "go with the vibes" when using AI tools to create applications.[\[19\]](#cite_note-19)

### Quality of code and security issues

\[[edit](/w/index.php?title=Vibe_coding&action=edit&section=5 "Edit section: Quality of code and security issues")\]

Vibe coding has raised concerns about understanding and accountability. Developers may use AI-generated code without fully comprehending its functionality, leading to undetected bugs, errors, or [security vulnerabilities](/wiki/Security_vulnerability "Security vulnerability").[\[20\]](#cite_note-20) While this approach may be suitable for [prototyping](/wiki/Software_prototyping "Software prototyping") or "throwaway weekend projects" as Karpathy originally envisioned, it is considered by some experts to pose risks in professional settings, where a deep understanding of the code is crucial for [debugging](/wiki/Debugging "Debugging"), maintenance, and [security](/wiki/Computer_security "Computer security"). *[Ars Technica](/wiki/Ars_Technica "Ars Technica")* cites Simon Willison, who stated: "Vibe coding your way to a production codebase is clearly risky. Most of the work we do as software engineers involves evolving existing systems, where the quality and understandability of the underlying code is crucial."[\[1\]](#cite_note-Edwards-2025-1)

In May 2025, [Lovable](/wiki/Lovable_\(company\) "Lovable (company)"), a Swedish vibe coding app, was reported to have security vulnerabilities in the code it generated, with 170 out of 1,645 Lovable-created [web applications](/wiki/Web_application "Web application") having an issue that would allow personal information to be accessed by anyone.[\[21\]](#cite_note-21)[\[22\]](#cite_note-22)

### Task complexity

\[[edit](/w/index.php?title=Vibe_coding&action=edit&section=6 "Edit section: Task complexity")\]

Generative AI is highly capable of handling simple tasks like basic algorithms. However, such systems struggle with more novel, complex coding problems like projects involving multiple files, poorly documented libraries, or critical code that has real-world impacts.[\[23\]](#cite_note-:0-23)

### Challenges with debugging

\[[edit](/w/index.php?title=Vibe_coding&action=edit&section=7 "Edit section: Challenges with debugging")\]

LLMs generate code dynamically, and the structure of such code may be subject to variation.[\[24\]](#cite_note-FastCompany2025-24) In addition, since the developer did not write the code, they may struggle to understand syntax/concepts that they themselves have not used.[\[23\]](#cite_note-:0-23)
