如果你是习惯了 Claude Code、Cursor 或者 Windsurf 这些现代 AI 编程工具的开发者，相信你一定对 **`@`** 这个符号产生了肌肉记忆——只要输入 `@`，就能迅速引用文件，无需切出窗口，无需繁琐的复制粘贴，直观且高效。

但这种流畅的 "心流" 体验，一旦回到 Obsidian 写笔记时，往往就会戛然而止。

想在笔记里引用一个本地文件的路径，要么手动敲漫长的路径名，要么切到文件资源管理器去复制路径，过程特别打断思路。我常想，Obsidian 作为一个**以本地文件为核心**的知识库工具，怎么能没有这个功能呢？

找了一圈，社区里确实没有特别顺手的方案。**那就自己动手吧**——于是就有了 **Mention Path** 这个插件。

现在，你在 Obsidian 里也能享受到像在 IDE 里一样的丝滑体验：打个 `@`，文件路径即刻上屏。

![](http://cdn.cs-magic.cn/picgo/demo.gif)

## 为什么要造这个轮子？

核心痛点非常简单：**路径引用的割裂感**。

在 Obsidian 的原生体验中，虽然双链 `[[Link]]` 很强大，但很多时候我们需要的是**文件路径字符串**（比如在代码块中引用、在 Frontmatter 中配置、或者在普通的文本描述中）。

Mention Path 的设计初衷，就是为了填补这个微小但高频的交互空白。它不是要取代双链，而是提供一种**更符合极客直觉的路径输入方式**。

## 核心体验：像写代码一样写笔记

### 1. 触发：肌肉记忆的延续

插件的核心交互极其克制：在笔记中输入 `@` 符号，即可唤醒自动补全面板。

为了不干扰正常的写作（毕竟 `@` 也是常用的标点），我们做了防误触处理：**只有在空格后面，或者行首输入时**，才会触发补全。

如果你不喜欢 `@`，完全可以在设置里把它改成 `#`、`/` 或者任何你顺手的字符。

### 2. 导航：给极客的路径漫游

既然是文件路径工具，对目录层级的掌控必须精准。Mention Path 完美复刻了命令行的操作习惯：

*   **父目录跳转**：输入 `../` 直接跳到上一级。想往上跳两级？那就 `../../`。
*   **根目录直达**：文件藏太深？输入 `~/` 一步到位回到 Vault 根目录，从头开始找。

![](http://cdn.cs-magic.cn/picgo/CC%E4%B8%8A%E4%B8%8B%E6%96%87%E6%9C%BA%E5%88%B6-2025-12-02-154538.png)


### 3. 穿透：流畅的文件夹钻取

很多补全插件在选中文件夹时会直接上屏，但这往往不是我们想要的。

Mention Path 做了一个贴心的设计：**Folder Drill-down**。当你选中一个文件夹时，它不会关闭候选框，而是直接**进入这个文件夹继续浏览**。你可以一路回车点下去，直到找到目标文件，整个过程不需要手指离开键盘。

## 细节打磨：不仅仅是自动补全

### 递归搜索与智能排序

文件太多找不到？直接打字搜索。

比如输入 `readme`，插件会自动**递归搜索**当前目录下的所有子文件夹。结果列表里不仅有文件名，还会清晰地显示相对路径。

排序逻辑也经过了精心调优：
1.  `~/` 和 `../` 等导航指令永远置顶。
2.  **文件夹** 优先于 **文件** 展示。
3.  同类型按字母排序，且**层级越浅的越靠前**。

这样保证了你最可能需要的选项，总是在最顺手的位置。

### 相对路径的哲学

选中文件后，Mention Path 插入的是**相对路径**，而非绝对路径。

```ad-tip
title: 为什么坚持用相对路径？
相对路径（Relative Path）是指从当前文件位置指向目标文件的路径，不包含盘符或根目录信息。

**优势**：
1. **可移植性**：当你的 Vault 在不同电脑间同步（比如 Mac 到 Windows），或者你把整个 Vault 文件夹移动了位置，相对路径永远不会失效。
2. **简洁性**：相比于冗长的绝对路径，相对路径更短、更易读。
```

## 结语

Mention Path 是一个小而美的插件，它只做一件事：**让文件路径的引用变得毫不费力**。
